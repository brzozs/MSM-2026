## 1. Source admission and provenance

An API being free to call does not make all its records public domain. Every enabled dataset needs a registry entry containing `source_id`, endpoint, dataset/study ID, coverage, measurement type, license/terms URL, required attribution, redistribution scope, refresh interval, request budget, original spatial precision, source period, and permission-review date. Set `redistribution_approved=false` until the specific product's terms are checked. Unknown or incompatible rights cause exclusion with a visible source-status reason.

Use CC0 and CC BY observation records for redistributable biodiversity bundles. Exclude NC/ND/all-rights-reserved records from that bundle policy. eBird is a distinct noncommercial, terms-governed integration: keep the key server-side, review its data-access terms, publish only the permitted display/aggregate product, and do not imply the feed is CC0. Media licenses are separate; the first release downloads no photos or audio.

Every retained record includes source ID and original ID, canonical origin ID for deduplication, observation/valid time, retrieval time, source license/attribution, taxon and life stage where known, reported coordinate uncertainty, public-coordinate/geoprivacy status, source quality flags, and the run ID. Missing precision is unknown, never zero. Do not reconstruct hidden coordinates. Public point layers require openly published coordinates and uncertainty at most 1,000 m; otherwise retain only a source-justified coarse aggregate or exclude from fine-scale analysis. Keep public coordinates only, and never join a randomized obscured point to a specific trail/cell as if exact.

### A defensible $0 R2 delivery boundary

Direct public R2 URLs expose unbounded billable reads even when egress is free. Use a **private** bucket behind a **Workers Free** gateway on `workers.dev`; at most one object `get` is allowed per accepted request, including a PMTiles byte-range request. The provider's 100,000/day Free worker ceiling bounds that path to at most 3.1 million reads in a 31-day month, before accounting for cache hits. Add at most 100,000 ETL/admin reads: 3.2 million stays below the 10 million free Class B allowance. This is a capacity argument for the proposed design, not a claim about an existing account.

The bound requires all of the following: R2 remains private; no alternate public endpoint exists; the gateway stays on Workers Free; no more than one bucket read occurs per request; no retries/subrequests multiply reads; ETL operations remain bounded; unrelated account usage is included; and stored bytes stay below the ceiling. Test these invariants. Verify account billing/enrollment conditions before activation. If these conditions cannot be satisfied, leave R2 delivery disabled and publish the small bounded Pages snapshot. Provider-required payment enrollment is not permission to incur charges. No purchased domain is needed.

## 4. ETL, spatial resolution, and retention

Use cron `17 */6 * * *` UTC on the default branch once the implementation is reviewed and merged, plus `workflow_dispatch` for authorized maintainers. GitHub scheduled jobs may be delayed and do not execute just because a workflow exists on a feature branch. A delayed job changes freshness; it never causes a false “live” badge. Stop a run after 15 minutes or the configured source-byte/request budget.

One run performs:

1. Acquire the workflow concurrency slot; load last committed source checkpoints and the immutable prior manifest. Confirm approved source registry entries and remaining quotas.
2. Fetch pilot incremental records in bounded pages. Re-read a 48-hour overlap, validate and deduplicate, and record rejected-record counts. Timeouts: 10 seconds connect / 30 seconds response; at most three attempts with `Retry-After` or exponential backoff/jitter for 429/5xx. Authentication and schema errors fail that source immediately.
3. Refresh a source only on its own schedule. Annual health/population data do not become “live” because today's ETL touched them. Run source adapters independently; preserve prior licensed evidence with its actual age when one source fails.
4. Normalize taxonomy, units, UTC time, coordinates, FIPS strings, quality flags, and source precision. Spatially join point records to H3 and prepared county intersections. Weather uses at most 200 selected pilot anchors, with nearest eligible land anchor within 25 km; no anchor in range means missing weather. Save anchor distance and original model resolution.
5. Calculate model components from that generation's inputs; mark stale/absent dependencies. Serialize only eligible sparse cells. Global H3 res-5 has 2,016,842 cells and res-7 has 98,825,162; storing every cell and time frame cannot fit this system. [H3 statistics](https://h3geo.org/docs/core-library/restable/).
6. Validate schemas, time consistency, null propagation, row/byte/operation limits, license admission, and county allocation conservation. Supabase writes are a bounded transaction; export/purge older pilot rows before admitting a new oversized batch.
7. Upload immutable artifacts under a generation prefix, verify sizes/hashes, then publish `current.json` last. A failed partial upload cannot move the current pointer. Update successful-source checkpoints only after publication; reruns are idempotent by original IDs and generation.

Retention defaults and admission limits:

| Data | Keep / cap |
|---|---|
| Supabase base/extensions + reference data | Reserve 100 MB before assigning any application-data budget; measure actual database usage. |
| Pilot observations | At most 50,000 current rows and 30 days; licensed longer history belongs in bounded R2 archives. Old GBIF baseline may be summarized without loading every raw occurrence. |
| H3 cells/intersections | At most 10,000 res-5 cells plus 10,000 prepared res-7 detail cells, only where needed; simplified geometry and measured bytes. |
| Current regional/cell summaries | One published generation's selected current-day summaries; no hourly × global × pathogen history table. |
| Hourly weather | Process in batch memory/files and bounded R2 artifacts; do not retain all forecast hours in Postgres. |
| Public snapshots | Daily frames D-7 through D+7; recent generation rollback window 48 hours; content-addressed shared artifacts referenced rather than duplicated. |
| Raw source archive | At most 7 days / 1 GB total; raw radar is excluded from recurring runs. Preserve source/checksum metadata after raw expiry. |
| Total R2 objects | Projected total below 7.5 GB including previous generations, raw data, and staging. Delete unreferenced expired prefixes; never delete current/previous manifest dependencies. |

The DB storage budget is a measured gate, not a guarantee based on row counts. Include GiST/B-tree indexes, TOAST, free space, and extension overhead. Check `SELECT pg_database_size(current_database());` before and after a batch and before any large raster/geometry import. Supabase is rebuildable from versioned references and current licensed snapshots; use small periodic logical backups within the egress budget, since Free does not promise automatic backups.

## 5. Static publication and cache behavior

Publish a small manifest, a coarse overview, per-day/per-region H3 summaries, optional res-7 region shards, bird paths, original health boundaries, source status, and optional regional PMTiles. Keep `.json.gz` objects as gzip-encoded JSON with correct `Content-Type: application/json` and `Content-Encoding: gzip`; browsers decode them once. A `.gz` suffix alone does not establish correct HTTP encoding.

For `.pmtiles`, serve the archive without whole-object HTTP gzip so byte offsets remain valid. Support single `Range` requests, 206, `Content-Range`, `Accept-Ranges`, ETag, 416, and HEAD (HEAD uses at most one R2 operation and is counted in the same budget). Expose the range/cache headers through CORS and allow the app's actual origin. Deny multi-range and arbitrary paths before bucket access. [Official PMTiles storage requirements](https://docs.protomaps.com/pmtiles/cloud-storage).

Immutable generation objects use `Cache-Control: public, max-age=31536000, immutable`; `current.json` uses `max-age=60` with a five-minute stale-while-revalidate window. The gateway Cache API is best effort and must preserve range/encoding semantics; correctness and cost caps do not depend on a cache hit. Use one R2 object operation on a miss, never HEAD plus GET. The `r2.dev` development URL is not the production CDN/caching solution. [R2 public-access documentation](https://developers.cloudflare.com/r2/buckets/public-buckets/).

Typical initial landing path: app assets → current manifest (target below 20 KB compressed) → overview (below 250 KB compressed) → selected-region frame (below 500 KB compressed). Only fetch the selected day and viewport; cache adjacent dates after idle. Fall back to the Pages last-good snapshot after static-host timeout/error, with its true date and degraded status.

## 6. Deployment, secrets, and operational failure

Implement CI on task PRs: TypeScript check, web unit tests, Python tests, PostGIS fixture integration, a production web build, and browser smoke tests. GPU timing is an additional manual release check. Pin workflow actions by commit and grant read-only repository permissions except the narrowly scoped deployment step. Untrusted fork PRs receive no provider secrets.

After independent PR audit and authorized integration, publish the Vite app to Pages; provision only the selected free providers; apply PostGIS migrations; configure the private R2 bucket and Free gateway; then enable batch publishing. Keep app deployment, scheduled data publishing, and optional Render API rollout independent so a broken model generation cannot take down the site. Roll back the app version and the data manifest separately. This document does not authorize that deployment.

Server/job secrets: `EBIRD_API_KEY`, `SUPABASE_DATABASE_URL`, bucket-scoped R2 upload credentials, Cloudflare deployment token, and optional Upstash credentials. Browser configuration may contain only public static origins and the optional API URL; never put server secrets behind a `VITE_` prefix. Enable Postgres RLS on working tables; browser roles have no base-table access. Supabase Auth/RBAC is a later feature, not required for anonymous map reads.

FastAPI uses a bounded connection pool and a select-only role, statement timeout 2 seconds, result cap 500 cells, allowlisted metrics, and validated identifiers. Do not accept SQL, an arbitrary upstream URL, or unbounded geometries. Begin with read-only endpoints. If enabling shared limits through Upstash, allow at most 30 detail requests/minute/client and fail closed if the counter service is unavailable. Provide static detail while the API wakes; do not repeatedly retry or run synthetic traffic to prevent free-tier sleep.

Operational statuses are `fresh`, `stale`, `unavailable`, `insufficient_data`, and `not_applicable`. Six-hour observations become stale after 24 hours; weather becomes stale 12 hours after forecast initialization, and past its valid horizon is unavailable. Annual/cumulative surveillance always shows its actual period; it is not assigned a live freshness window. Record job duration, source requests/bytes, newest evidence time, eligible/rejected rows, DB bytes, R2 bytes/operations, artifact sizes, and per-layer coverage in a small status artifact.

When an upstream source fails, retain the previous source data with its timestamp, mark affected components, and publish only if the minimum known-good schema/provenance contract still holds. For an oversized batch, corrupted manifest, exhausted quota, denied source permission, or an unknown license, stop that path explicitly. Retain the last good version; do not silently substitute invented measurements or enable a paid tier.
